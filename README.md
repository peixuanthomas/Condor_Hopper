# Condor Hopper

通过 Python 和 kRPC 控制 KSP 中的 `Condor-Hopper`：默认全油门竖直上升至**海拔 20000 米**后熄火，保持姿态滑行，下降后用栅格舵修正落点，再重新点火减速着陆。

着陆目标为**南纬 0°12′21″、西经 74°28′23″**（`-0.20583333, -74.47305556`），距发射台约 1442 米。程序从游戏读取目标地面海拔，落点允许误差为 **5 米**。

## 准备与运行

需要 Python 3.11 或更新版本，以及已开启 kRPC 的 KSP。当前程序按一台可重新点火的发动机、四片栅格舵和四条支腿检查载具。

试飞前将飞行器放回发射台，恢复燃料，收起栅格舵和支腿，保持静止、竖直。游戏应正常播放；数据停止更新超过三秒，程序会停止控制。

在本目录安装命令和依赖：

```powershell
python -m pip install -e .
```

安装后可在任意目录使用：

```powershell
condor-hopper probe
condor-hopper fly
condor-hopper fly --target-altitude 10000
condor-hopper --help
```

`probe` 只检查状态，输出载具、燃料、目标坐标和距离。`fly` 直接执行一次完整飞行，默认海拔 **20000 米**熄火，无需 `--execute`；`--target-altitude` 可指定其他熄火海拔。直接输入 `condor-hopper` 或使用 `--help` 查看命令说明。

仍可在项目目录使用 `python main.py probe` 和 `python main.py fly`。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--target-altitude` | `20000` | 发动机熄火的海拔，单位米；只用于 `fly` |
| `--address` | `127.0.0.1` | kRPC 服务器地址 |
| `--rpc-port` | `50000` | 控制连接端口 |
| `--stream-port` | `50001` | 飞行数据端口 |

目标坐标保存在 [vehicle.py](condor_hopper/vehicle.py) 的 `target_latitude` 和 `target_longitude` 中。修改后先运行 `probe` 核对。

## 飞行过程

1. **上升**：使用 kRPC 自动驾驶保持竖直，全油门上升，中途不减速。达到熄火海拔后关闭发动机，飞行器仍会继续上升。
2. **滑行**：保持方向，确认已经下降后才展开栅格舵。下降姿态由 Python 控制，保持机头朝上、发动机端先行。
3. **修正落点**：用栅格舵调整航向。从目标上方 12000 米以下开始计算着陆点火时机，检查推力、剩余燃料和转向是否足够。采纳点火时刻后不再推迟。
4. **点火着陆**：按实测高度、速度和空气作用调整推力，发动机喷口和栅格舵共同控制方向。空气与发动机的侧向作用接近时，暂停追点并先消除横移，避免转向方向反复改变。支腿相对目标地面的高度降至 **800 米**时展开；点火时机仍由程序计算。
5. **接地**：参考 BoosterGuidance，最后 200 米朝反速度方向并稍向上偏转，只减速、消除水平速度，不再追逐位置偏差，也不会因高度低就强行转正。最后 1000 米若预计转正前横移就会反向，会提前进入持续刹车。横移消失后自然转正；第一条支腿接地就熄火并停止转向，随后检查是否稳定。

着陆采用在下降途中点火、连续减速至接地的方式，不通过近地面悬停或反复平移追点。数学计算参考 Blackmore 等公开的凸优化着陆研究；公式、论文链接和模型限制见 [LANDING.md](LANDING.md)。

程序确认成功需要同时满足：

| 检查项 | 条件 |
| --- | --- |
| 落点偏差 | 不超过 5 米 |
| 升降速度 | 绝对值不超过 1 米/秒 |
| 水平速度 | 不超过 0.5 米/秒 |
| 箭体倾角 | 不超过 3° |
| 接地稳定 | 至少三条支腿接地，速度和姿态满足上述条件，持续一秒 |

2026-10-23 的记录 `20261023_151818_568456` 使用 **10000 米熄火设置**。实测熄火海拔约 **10015 米**，最高海拔约 **31395 米**。着陆点火时相对目标地面的高度约 **6563 米**，支腿仍收起；降至约 **795 米**时首次发出展开指令，符合 800 米门槛。

首次支腿接地时，距目标 **160.75 米**，下降速度约 **0.70 米/秒**，水平速度约 **9.33 米/秒**，倾角约 **0.53°**。约 200 米处水平速度曾降至 **2.81 米/秒**，随后反向增大，接地后侧翻，程序关闭发动机并退出。该记录用于复现近地横移问题，`summary.json` 中的 `success` 为 `false`。

## 飞行记录与验证

每次飞行写入项目目录下的 `flight_logs/时间/`，从其他目录运行命令也保存在这里。每条数据立即保存：

| 文件 | 内容 |
| --- | --- |
| `preflight.json`、`config.json` | 起飞状态、燃料、目标坐标和熄火海拔 |
| `telemetry.csv` | 高度、速度、水平加速度、是否持续刹住横移、落点偏差、姿态、油门、实际推力、转向输入及接地数量 |
| `plan_*.json` | 采纳的点火方案、预计轨迹、推力和耗油，以及重新计算的终点误差 |
| `summary.json` | 成功与否、最终偏差、速度和停止原因 |
| `error.txt` | 异常退出时的详细信息 |

`flight_logs/` 不纳入 Git，复查或共享试飞时需单独保留对应目录。飞行失败后需要手动重置载具，程序不会自动重置游戏。

运行离线测试：

```powershell
python -m pip install -e ".[dev]"
python -m pytest
```

测试覆盖上升与滑行顺序、下降转向、点火时机、800 米支腿展开、推力与耗油限制、带转向延迟的下降，以及末段水平刹车。离线通过不代表游戏内已经稳定着陆。

## 代码位置

- [cli.py](condor_hopper/cli.py)：`condor-hopper` 命令入口、飞行循环和记录。
- [main.py](main.py)：保留直接运行 Python 脚本的入口。
- [vehicle.py](condor_hopper/vehicle.py)：读取游戏数据、检查载具、控制发动机与舵面。
- [mission.py](condor_hopper/mission.py)：飞行阶段、姿态控制与末段减速。
- [landing.py](condor_hopper/landing.py)：点火时机、轨迹计算和运动检查。
- [CHANGELOG.md](CHANGELOG.md)：改动记录。

本机 kRPC 0.5.2 的舵面转动力带有正负号；Python 按各部件转动力的幅值计算，避免相加时抵消。上升和滑行仍使用原有自动驾驶，下降不依赖服务端自动驾驶的转向计算。

kRPC 参考：[飞行数据](https://krpc.github.io/krpc/latest/python/api/space-center/flight.html)、[自动驾驶](https://krpc.github.io/krpc/latest/python/api/space-center/auto-pilot.html)、[部件](https://krpc.github.io/krpc/latest/python/api/space-center/parts.html)。
